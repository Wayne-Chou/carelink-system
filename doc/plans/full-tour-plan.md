# 完整操作導覽：計畫與腳本（規劃中，待確認）

> **狀態：第 0 期已完成；第 1 期起待腳本確認後開始。** 已確認事項見「八」。

## 一、目的與範圍

讓委託方只看網址就能自己理解並操作整個系統，也用來錄製說明影片。放在右下角「?」選單的「完整操作導覽」，分三部分，可以從任一章或任一情境開始：

- 第一部分：帳號與角色（5 章）
- 第二部分：完整流程主線（7 章）：橘燈開案、轉介成功、結案
- 第三部分：例外與分支情境（4 組、51 個情境）：帳號、資源、評估與判讀、個案

## 二、技術做法

### 2.1 導覽引擎（新做，與現有各頁導覽分開）

現有的各頁導覽一次只在一頁內框起區塊；完整導覽要跨頁、切換角色、等使用者按按鈕，所以另做一個引擎，畫面框選仍用同一套 driver.js 1.4.0。

每一步的設定（全部寫在 `src/config/fullTour/` 的設定檔）：

| 欄位 | 用途 |
| --- | --- |
| role | 這一步用哪個角色（民眾為未登入）；和上一步不同時自動以該角色的示範帳號登入，畫面先顯示「現在切換成○○」 |
| page | 要在哪一頁（路由名稱與要帶入的資料，例如「這個情境的個案」） |
| target | 框起頁面上的哪個 data-tour 標記；沒有時只顯示置中的說明框 |
| title、text | 說明泡泡的標題與內容（2～3 句） |
| action | `next`：按「下一步」前進；`click`：提示使用者按框起的按鈕，按完、畫面更新後自動接下一步；`fill`：同 next，但說明框多一顆「幫我填入範例」 |
| fill | 這一步「幫我填入範例」要填哪一份範例資料 |
| waitFor | `click` 之後要等到的結果（例如網址變成個案頁、出現「已記錄首次聯繫」） |

- **每一步都要按「下一步」才前進**，不會自動跳步。只有 `click` 步驟會在使用者按了框起的按鈕之後自動接下一步，因為那一步就是在等使用者操作。
- 說明框上方固定顯示目前位置，例如「第三部分　個案情境 3／11　第 2 步／5」。
- 按鈕：「上一步」「下一步」「結束導覽」；`fill` 步驟另有「幫我填入範例」。
- 找不到要框的區塊時（例如畫面還在載入），最多等 3 秒；仍找不到就顯示置中說明框，並提示「畫面和預期不同，可以按『重新準備這一段』」。

### 2.2 自動準備資料

- 從某一章或某一情境開始時，先清空資源、評估、個案，再用與頁面操作相同的程式建立這一段需要的資料，例如「一筆首次聯繫已逾期的個案」。
- 需要「過了一段時間」的情境（例如逾期 72 小時、三個月後確認、驗證過期、連結過期），把資料的日期往前調整，不改變系統時間。
- 「重新開始」清空資源、評估、個案，以及導覽過程中申請或建立的帳號、模擬信箱的信件、資源點綁定，再從第一部分開始。系統內建的示範帳號不受影響。

### 2.3 幫我填入範例

- 每張表單都有固定的範例內容，每次填入都一樣（見「三、範例資料」）。範例內容寫在設定檔，各頁的表單提供一個統一的填入入口。
- 填入後仍由使用者按頁面上的送出按鈕，讓影片中看得到實際操作。

### 2.4 進度與中斷

- 進行中可以隨時按「結束導覽」。進度記在 sessionStorage，透過共用的儲存工具讀寫。
- 下次從「?」選單打開時，詢問要「從中斷處繼續」還是「重新開始」。繼續時，如果這一段的資料已經不在（例如瀏覽器關過），自動重新準備這一段的資料，從這一段的第 1 步開始。

### 2.5 與現有功能共存

| 現有功能 | 完整導覽進行中 |
| --- | --- |
| 歡迎卡片 | 不自動顯示（切換角色時本來會第一次顯示的，也先不顯示），也不記為已看過 |
| 各頁自動導覽 | 不自動執行；若正在執行，先結束 |
| 「?」選單 | 仍顯示，第一項改為「完整操作導覽：結束」；其他項目在導覽中先隱藏，避免同時開啟兩種導覽 |
| 載入示範資料（「?」選單） | 導覽中隱藏（同上）；完整導覽自己準備每一段需要的資料，不使用示範資料 |
| 評估填寫頁 | 這一頁沒有「?」按鈕；完整導覽仍會帶使用者到這一頁並顯示說明框（說明框本身有「結束導覽」） |
| 自動導覽開關 | 只影響歡迎卡片與各頁自動導覽，不影響完整導覽 |

結束完整導覽後，各功能恢復原狀。

## 四、導覽腳本

標記說明：
- 〔角色〕：這一步使用的角色；換角色時先顯示「現在切換成○○」。
- 頁面：這一步所在的頁面。
- 框起：要框起的區塊。
- 【按】：等使用者按框起的按鈕，按完自動接下一步。
- 【填】：說明框上有「幫我填入範例」。
- 其他步驟都按「下一步」前進。

## 五、對照程式補上的狀態

以下是你的清單沒有列到、目前程式中確實存在的狀態，已加入第三部分（標「補」）：

- 帳號：
  - 申請 Email 重複或為示範帳號（A8）
  - 不能停用自己與示範帳號（A9）
  - 資源點申請時綁定資源，審核時可改綁（A10）
  - 建立系統管理員時會再確認一次（併入第一部分第 5 章）
  - 設定密碼連結只能用一次（併入 A4、A5）
- 資源：
  - 編輯時風險等級變更要填調整說明（B5）
  - 郵遞區號自動帶入、貼地圖連結帶座標（B10）
  - 附近搜尋的各種結果，包括無座標、拒絕定位、逾時、不支援（B11）
  - 改綁與解除綁定（B12）
  - 系統管理員從資源列表進入資源端（B13）
  - 已終止資源的資源端後台不能回報（B14）
  - 人員資格只有綠燈與紅燈（併入 B5）
- 評估與判讀：
  - Q3、Q4、Q8、Q10 的追問提示（C11）
  - 「想找人聊聊」與其他選項互斥（C12）
  - 未開案前可修改判讀（C13）
  - 健康管理員唯讀、判讀人員看不到個案頁（C14）
  - 連續婉拒 3 次改為 6 個月後再確認（併入 C4）
  - 下一筆未判讀（併入第二部分第 3 章）
- 個案：
  - 進入追蹤需最新連結成功（D12）
  - 重新選擇資源後追蹤重新排程（併入 D3）
  - 已刪除資源仍顯示當時名稱（併入 D5）
  - 結案後唯讀（D13）
- 權限與網址：
  - 資源點打開後台首頁直接進入資源端後台（併入 A7）
  - 舊網址與舊信件連結自動導向新網址（併入 A7）
- 程式中沒有、但清單可能預期有的（不做情境，在導覽中說明「目前沒有」）：
  - 資源名額不會因轉介自動扣減
  - 資源點只能回報一次連結結果，之後由健康管理員追蹤
