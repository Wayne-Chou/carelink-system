# CareLink 註冊與帳號管理規格 v1

Oct 28, 2026 · @hank

## 概述

工作人員以「申請、審核、開通、設定密碼」的流程取得帳號：判讀人員、健康管理員、資源點自行申請（申請時不設密碼），由系統管理員審核；審核通過後系統寄出設定密碼信，設定密碼後才能登入。系統管理員、資源管理員只能由系統管理員建立。系統的通知信都寫入模擬信箱，不實際寄出。

**原型階段：帳號、密碼、重設密碼連結、通知信都存在瀏覽器（sessionStorage，關閉分頁後清除），密碼未加密，權限只在前端檢查。正式版需改由後端處理帳號、密碼雜湊、Email 寄送與權限，並移除模擬信箱。**

相關程式：

| 檔案 | 內容 |
| --- | --- |
| src/config/accounts.js | 帳號狀態、醫事人員類別、確認方式、密碼規則、連結期限、依角色的申請欄位 |
| src/services/accountService.js | 註冊申請、審核、停用與重新啟用、建立帳號、設定與重設密碼 |
| src/services/mailService.js | 模擬信箱 |
| src/utils/auth.js | 登入、登入狀態、帳號狀態檢查、資源點綁定 |
| src/pages/Register.vue、AccountManagement.vue、ForgotPassword.vue、ResetPassword.vue、Mailbox.vue | 頁面 |

角色與權限見 doc/specs/assessment-schema.md 第一節；帳號管理需要權限 account.manage（只有系統管理員）。待確認事項見 [doc/open-questions.md](../open-questions.md)「註冊與帳號」。

## 一、帳號狀態

| 狀態 | 代碼 | 可以登入 |
| --- | --- | --- |
| 待審核 | pending | 否 |
| 已啟用 | active | 是（需已設定密碼） |
| 已退回 | rejected | 否 |
| 已停用 | suspended | 否 |

### 登入時的訊息（不透露帳號狀態）

| 情況 | 登入時顯示 |
| --- | --- |
| Email 不存在、密碼錯誤 | 登入失敗訊息（見下） |
| 還沒有密碼的帳號：待審核、已退回、已開通但尚未設定密碼 | 登入失敗訊息（與密碼錯誤完全相同） |
| 已設定密碼且密碼正確，但帳號已停用 | 帳號已停用：原因。如有疑問請聯絡系統管理員 |
| 已設定密碼且密碼正確，帳號已啟用 | 登入成功 |

登入失敗訊息：「Email 或密碼錯誤。若您已申請帳號但尚未設定密碼，請查看 Email 通知，或使用忘記密碼重新取得連結。」

- 待審核、已退回、已開通的結果只以 Email 通知（審核通過信附設定密碼連結；退回信附原因與重新申請連結），登入頁不顯示。
- 已設定密碼的帳號：密碼正確後才檢查狀態，避免輸錯密碼的人得知帳號狀態。
- 尚未設定密碼或連結過期時，使用登入頁的「忘記密碼」重新取得連結。
- 示範帳號寫在程式中，視為已啟用；改版前註冊、沒有狀態欄位的帳號也視為已啟用。
- 已登入的帳號被停用後，下次讀取登入者時自動登出。

```text
送出申請（不設密碼）→ 待審核 ─┬→ 通過 → 已啟用（寄出設定密碼信）→ 設定密碼 → 可以登入
                               │            已啟用 ⇄ 停用／重新啟用 → 已停用
                               └→ 退回 → 已退回 → 用同一個 Email 重新申請 → 待審核
系統管理員建立 → 已啟用（寄出設定密碼信）→ 設定密碼 → 可以登入
```

## 二、註冊申請

可申請的角色：判讀人員、健康管理員、資源點。系統管理員、資源管理員不開放申請。

### 共同欄位（皆必填）

| 欄位 | 中文名稱 | 說明 |
| --- | --- | --- |
| name | 姓名 |  |
| email | Email | 登入帳號，不分大小寫 |
| phone | 手機 | 09 開頭共 10 碼，可含連字號 |
| organization | 目前任職或服務單位 |  |
| jobTitle | 職稱 |  |
| role | 申請角色 | reader、manager、provider |
| supervisorName | 目前單位主管或聯絡人姓名 | 見下方說明 |
| supervisorContact | 目前單位主管或聯絡人電話或 Email | 見下方說明 |
| reason | 申請理由 |  |
| consentAt | 個資保護與保密同意 | 必須勾選，記錄同意時間 |

主管或聯絡人欄位下方的說明：「請填寫目前單位可協助確認身分的主管或聯絡人，審核時可能會向對方確認；沒有直屬主管者，請填機構負責人、里長等可確認身分的人。」

註冊時不設密碼（password 為 null），審核通過後由設定密碼信設定。

### 依申請角色的額外欄位（存在 details）

| 角色 | 欄位 | 中文名稱 | 必填 |
| --- | --- | --- | --- |
| 判讀人員 | medicalType | 醫事人員類別（醫師、護理師、營養師、其他） | 是 |
| 判讀人員 | licenseNo | 醫事人員證書字號 | 是 |
| 判讀人員 | institution | 執業機構 | 是 |
| 健康管理員 | employeeIdOrEmployer | 員工編號或聘任單位 | 是 |
| 資源點 | resourceId | 要綁定的資源 | 是 |
| 資源點 | orgName | 機構名稱 | 是 |
| 資源點 | registrationNo | 立案字號 | 否 |
| 資源點 | orgContact | 機構聯絡電話或 LINE | 是 |

### 規則

- Email 不能與示範帳號，或已啟用、待審核、已停用的帳號重複。
- 送出後狀態為待審核，畫面說明需等候審核、結果會以 Email 通知，審核通過時會寄出設定密碼連結；不會自動登入。
- 寄出「註冊申請已送出」給申請人，「有新的註冊申請」給所有已啟用的系統管理員（含前往審核的連結）。
- 已退回的 Email 可以重新申請：新申請覆蓋舊的（同一筆帳號、同一個 id），審核紀錄清空，狀態歷程保留先前的退回紀錄。
- 退回通知信附「重新申請」連結（/register?reapply=帳號 id），開啟註冊頁時帶入原本的申請資料；個資保護與保密同意需重新勾選。

## 三、帳號管理頁（/accounts，系統管理員）

- 依狀態分頁：待審核、已啟用、已退回、已停用、全部；「全部」中待審核排最前面（先申請的在前），其餘依建立時間新的在前，示範帳號在最後且只能檢視。
- 首頁快捷區「帳號管理」；待辦「待審核帳號」與新申請通知信連到 /accounts?review=帳號 id，直接開啟該帳號的審核畫面。
- 頁首有「模擬信箱（原型展示用）」入口。

### 審核

| 欄位 | 說明 |
| --- | --- |
| review.decision | approve 通過、reject 退回 |
| review.methods | 確認方式，至少一種：電話、LINE、Email、查詢醫事人員證書、查詢立案資料、向主管確認、其他（需說明 methodOther） |
| review.reason | 退回原因，退回時必填，寫在退回通知信中 |
| review.note | 審核備註，選填，只有系統管理員看得到 |
| review.reviewer | 審核者 { name, email }，系統自動 |
| review.at | 審核時間，系統自動 |
| review.resourceId | 資源點通過時綁定的資源；預設為申請時選的資源，審核者可改 |

- 通過：狀態改為已啟用，寄「帳號已開通，請設定密碼」信，附設定密碼連結（7 天內有效）。判讀人員的醫事人員類別帶入 readerType（判讀頁自動帶入）；資源點同時完成資源綁定。
- 退回：狀態改為已退回，statusReason 為退回原因，寄「審核退回」信（附重新申請連結）。

### 停用與重新啟用

- 停用：只限已啟用的帳號，須填原因；不能停用自己的帳號與示範帳號。寄「帳號停用」信（附原因）。
- 重新啟用：只限已停用的帳號，說明選填。寄「帳號重新啟用」信。

### 建立帳號

- 欄位：姓名、Email（必填）、手機、目前任職或服務單位、職稱、角色（必填）；資源點須選綁定的資源；判讀人員可選醫事人員類別。
- 可建立全部角色，包括系統管理員（送出前再確認一次）；資源管理員只能從這裡建立。
- 建立後為已啟用，不設密碼；寄出「帳號已建立」信，內含設定密碼連結（7 天內有效，與重設密碼頁共用）。設定密碼前無法登入；連結逾時可用「忘記密碼」重新取得。
- Email 不能與任何現有帳號重複（含已退回的申請，請申請人重新申請）。

### 狀態歷程（history）

每次狀態變更新增一筆 { at, action, status, reason, actor }。action：apply 送出申請、reapply 重新申請、approve 審核通過、reject 審核退回、suspend 停用、reactivate 重新啟用、create 系統管理員建立。

## 四、設定密碼與忘記密碼

設定密碼與重設密碼共用同一頁：/reset-password?token=…

| 連結來源 | 用途 | 有效期限 |
| --- | --- | --- |
| 審核通過（帳號已開通，請設定密碼） | setup 設定密碼 | 7 天（SETUP_TOKEN_DAYS） |
| 系統管理員建立帳號 | setup 設定密碼 | 7 天 |
| 忘記密碼 | reset 重設密碼 | 60 分鐘（RESET_TOKEN_MINUTES） |

- 連結只能使用一次；設定成功後，同一帳號其他未使用的連結全部失效。
- 連結無效、已使用或已過期時，頁面提示「請在登入頁使用『忘記密碼』重新取得連結」，並附前往忘記密碼頁的連結。
- 忘記密碼（/forgot-password）：輸入 Email 後，不論 Email 是否存在都顯示「若此 Email 已註冊，我們已寄出重設密碼信」，避免透露哪些 Email 有帳號。只對已啟用的註冊帳號寄出（含尚未設定密碼的帳號）；示範帳號的密碼寫在程式中、不能修改，不寄。

## 五、密碼規則

至少 8 碼，需包含英文字母與數字。設定密碼、重設密碼都套用（註冊時不設密碼）。

## 六、模擬信箱（/mailbox，原型展示用）

- 所有通知信寫入模擬信箱，不實際寄出（註冊送出、審核通過、審核退回、帳號停用、重新啟用、建立帳號、設定與重設密碼）：

| 類型 | 代碼 | 收件人 | 連結 |
| --- | --- | --- | --- |
| 註冊申請已送出 | application_received | 申請人 | － |
| 有新的註冊申請 | application_new | 所有已啟用的系統管理員 | 前往審核 |
| 帳號已開通，請設定密碼 | approved | 申請人 | 設定密碼（7 天） |
| 審核退回 | rejected | 申請人 | 重新申請 |
| 帳號停用 | suspended | 該帳號 | － |
| 帳號重新啟用 | reactivated | 該帳號 | 前往登入 |
| 帳號已建立，請設定密碼 | account_created | 新帳號 | 設定密碼（7 天） |
| 重設密碼 | password_reset | 該帳號 | 重設密碼（60 分鐘） |

- 頁面依收件人分組，可開啟信件內容並直接點擊信中的連結。
- 入口在登入頁、帳號管理頁（也在註冊送出、忘記密碼頁），都標示「原型展示用」。
- 不需登入即可查看所有信件，僅供原型展示；正式版改由後端寄送 Email，沒有這一頁。

## 七、儲存（原型階段）

存在帳號儲存區（src/services/storage.js 的 ACCOUNT_STORAGE，目前為 sessionStorage）：

| key | 內容 |
| --- | --- |
| users | 註冊與建立的帳號（含申請資料、狀態、審核紀錄、狀態歷程；尚未設定密碼時 password 為 null） |
| providerBindings | 資源點帳號綁定的資源 |
| passwordTokens | 設定與重設密碼的連結 |
| mockMails | 模擬信箱的信件 |

## 八、原型階段的限制

- 密碼以明碼存在瀏覽器；正式版需由後端以雜湊保存。
- 重新申請連結以帳號 id 開啟，知道連結的人可以看到原本的申請資料；正式版應改用一次性的連結。
- 模擬信箱不需登入即可查看所有信件。
- 關閉分頁後所有帳號、申請與信件都會清除，只剩示範帳號。
